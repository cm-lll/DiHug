# COUNT分块审阅：当前禁用，仅提出一个待确认实现

现有COUNT不是块边数预测。原定义是对完整无向槽的p0按关系求μ，和完整X0关系边数m比较，再计算`λ/|M| * Σρ((μ-m)/s)`；s=sqrt(max(m,1))，ρ(u)=sqrt(1+u²)-1，λ=.001，M为可动关系。

本票只恢复CE抽块路径。block20.normal2遇到非零count_aux_weight直接拒绝；没有COUNT完整图更新或伪造适配成功。旧package/normal2.py是保留的192节点全查询源码，不能当本票入口。

唯一建议为**固定Xt、固定20块计划、参数不变的双遍精确链式法则**：

1. 第一遍扫完20块，将每块完整无向候选槽p0以FP64分关系累加，加入固定支持的常数贡献，得到μ；目标m始终来自完整X0。每块及时释放计算图，不保留20块激活。
2. 按完整μ计算真实数量项及其数量导数`a_r = λ/|M| * u_r/(s_r*sqrt(1+u_r²))`，并detach这些导数值。
3. 第二遍重算同一20块。各块反向`Σ_r a_r*Σ_{e in block,r} p0_e`；仅被原CE抽中的块另加`20*sumCE/S`。每份输入整体乘1/2，两份输入所有反向完成后只更新一次优化器及EMA。
4. 日志记录真实ρ损失；第二遍线性代理仅用于链式梯度，数值本身不能作为实际数量损失。

该方案数学上精确计算**当前20块预测上下文所定义的全关系数量目标及梯度**，不会把非线性惩罚套到20倍单块估计量上。不能宣称它等于旧rounds=1网络的损失：查询块参与Transformer，因而p0本身可能随上下文变化；本票没有证明分块与全查询概率相等。

重复计算还须控制实际实现：第一遍应保留和第二遍一致的grad-enabled计算/后端分派，再立即detach数量并释放图；不能仅用no_grad后假设PyG分派与grad-enabled一致。保存/恢复各块随机状态，验证重算概率的数值一致性；保持buffers不变。当前attention dropout实际未启用，也不应据此省略状态合同。固定ReFeX/NNLS数组可以在同一Xt内复用；学习投影、CN学习上下文须按梯度需要重算，不能缓存no-grad输出后冒充可导表示，不能跨优化器更新复用。

普通CE normal2是2前向/2反向；通用双遍方案是80前向/40反向（每份输入40前向/20反向）。增加78前向/38反向，非微小开销。IMDB A本次组件均值约前向1.86s/输入、反向2.81s/输入，以此粗估约261s/normal2，约28倍CE，尚未计字典编码/检查/IO；**不是C/E实测，也不是正式预算**。不同块的CN缓存与全图特征重算策略会改变成本。

每块显存仍至少要能容纳CE所需前后向。PubMed A的20块grad-enabled前向本票已OOM，因此该COUNT建议也不能解决它的本地显存准入。若要求旧全查询预测上下文本身严格不变，则本方案不满足，不能未经确认替换目标。

下一步只在明确确认该目标与额外成本后另票实现/验证。本票没有实现模型COUNT分块训练、没有改成新估计损失、没有新增前向。
